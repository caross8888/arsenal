# 커리어 급여 · 이적료 v1

## 통화와 기간

- 소속 구단 리그: ENG → GBP, KOR → KRW, JPN → JPY, 그 외 → EUR.
- GBP/EUR는 주급 중심, KRW/JPY는 연봉 중심. 보조 금액은 연봉/주급.
- 연봉 기준으로 기록하고 주급은 연봉 ÷ 52. 화면에서만 반올림한다.
- 게임용 고정 환율: EUR 1 = GBP 0.85 = KRW 1,500 = JPY 160.
- 은퇴카드 최고 주급과 통산 기본급 수입은 EUR로 통일한다.
- 실제 환율이나 미래 시즌 물가를 예측하는 모델이 아니다.

## 급여 계산

`api/_career_wages.js`에 기준 OVR, 기본 연봉, 하한과 완만한 상단을 정의한다.
별도 구단 임금 지수와 리그 일반 구단 보정치를 사용하며, 구단 명성을 임금 예산으로 대체하지 않는다.
실제 자료와 보정 전후 비교 및 자료 한계는 [급여 보정안](salary-calibration.md)에 기록한다.

OVR 구간별 연속 곡선과 해당 구단에서의 역할 기준에 구단 임금 지수, 최근 2시즌 활약, 나이, 첫 계약 보정, 공개된 유망주 등급을 적용한다.
최근 시즌 가중치는 2, 이전 시즌은 1이다. 평점과 출전 비율에 더해 FW는 골/도움,
MF는 도움 비중이 큰 공격 생산성, DF는 클린시트/도움을 사용한다.
활약 보정 범위는 0.8~1.2이며, 상단은 고정 금액으로 자르지 않고 증가 폭을 줄인다.
일본 성인/첫 프로 계약과 미국의 연령별 하한을 따로 적용한다.
숨은 재능, 선수 국적, 공유 시뮬레이션 난수는 급여 계산에 사용하지 않는다.

첫 프로 계약, 영구 이적, 재계약 시점에만 새 급여를 저장한다.
계약 중 잔류, 부상, 임대, 시즌 성적 변동만으로 기존 급여를 변경하지 않는다.
실제 이적 제안과 다음 시즌 서명 계약은 같은 계산으로 일치시킨다.
첫 계약은 기존 로직의 4년, 이후 계약은 기존 나이/시드별 기간을 따른다.
다른 통화로 이적해도 EUR 기준 기본급으로 증감률을 비교한다.

## 시즌 수입

한 시즌을 확정할 때 `row.finance`에 계약과 실제 지급 개월 수를 저장한다.
정상 시즌/부상/일반 임대는 12개월, 군 복무 기간은 구단 기본급에서 제외한다.
전역 시즌은 남은 6개월만 포함한다. 군인 수당, 세금, 보너스, 에이전트 비용은 계산하지 않는다.
대회 승부차기 대기/재개는 기존 시즌 초안 재계산 흐름을 사용하므로 같은 시즌을 이중 적립하지 않는다.

## 시장가치와 이적료

시장가치는 OVR·나이와 최근 활약으로 계산한다. 이적료는 시장가치에 잔여 계약 기간과
영입 구단 보정을 적용한다. 다음 시즌 시작 시 계약 만료라면 자유계약, 이적료 0이다.
이적료는 구단 간 거래 금액으로 선수의 연봉 수입에 합산하지 않는다.
이미 존재하는 은퇴카드의 최고 시장가치 산식과 커리어 점수는 변경하지 않는다.

## 이전 저장과 랭킹

급여 기록이 없는 시즌은 시간순으로 계산한다. 같은 구단에서 계약 기간이 남았으면 같은 금액을 유지한다.
임대 이동은 영구 이적으로 처리하지 않는다. 구형 은퇴카드에서 전역 시즌이 두 줄로 분리된 경우
나이로 묶고 복무/민간 개월 수를 구분해 한 해를 중복 합산하지 않는다.
기존 카드에 당시 계약/평점 정보가 없으면 저장된 OVR·나이·구단·출전·포지션별 기록과
고정 계약 기간 규칙을 사용한다. 실제 당시 조건을 완전히 복원하는 계산은 아니다.
UI에는 요청대로 별도 구분 문구 없이 동일한 최고 주급·통산 연봉 수입을 표시한다.

기존 랭킹 카드는 관리 도구 `scripts/backfill_career_finance.mjs`로 일회 계산해 카드의 `finance` 필드에 저장한다.
조회 API는 저장된 값을 그대로 반환하며 급여를 재계산하지 않는다. 점수·순위·시즌 원본은 변경하지 않는다.
새 커리어는 계약과 시즌 지급액을 기록하므로 이후 조회에서 당시 급여를 그대로 사용한다.
금액과 환율 규칙 변경 시 finance 버전을 올려 이전 지급 기록과 섞이지 않게 해야 한다.

## 검증

`node scripts/test_career_finance.mjs`

계약 유지, 제안/서명 일치, 통화 비교, 구형 카드, 임대·복무 지급 기간, 자유계약과
랭킹 카드 API의 저장값 조회/읽기 전용 동작을 검증한다.

`node scripts/test_career_finance_backfill.mjs`는 일회 반영의 충돌 방지·재실행·구형 키 처리를 검증한다.

### 운영 일회 반영

환경 시크릿 `KV_REST_API_URL`, `KV_REST_API_TOKEN`이 필요하다.
먼저 `node scripts/backfill_career_finance.mjs`로 대상 수를 확인한 후
`node scripts/backfill_career_finance.mjs --apply --backup /저장소밖/finance-before.json`으로 저장한다.
`.env.local`을 사용할 때는 `node --env-file=arsenal-dashboard/.env.local`을 사용한다.
구형/포지션별 랭킹에 연결된 모든 카드를 읽으며, 이미 `finance.v=1`인 카드는 건너뛴다.
저장 전 원문을 파일에 보관하고, Redis에서 원문 일치를 확인한 뒤 저장하여 실행 중 새로 등록된 카드를 덮어쓰지 않는다.
저장 후 검증하며 충돌 건은 재실행한다. 운영 데이터 파일은 저장소 외부에 두며 커밋하지 않는다.
`--public-out /저장소밖/cards.json`은 공개된 포지션별 상위 100명의 계산본만 저장하며 KV에는 쓰지 않는다.
운영 반영은 KV 자격증명으로 실행하고 완료 여부를 별도로 확인해야 한다.
