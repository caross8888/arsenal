# 커리어 모드 구현 계획

설계·밸런스는 `career-mode.md`, 동작 견본은 `mockup.html`. 이 문서는 그걸 실제 게임으로 옮기는 계획이다.
기존 미니게임(Who Am I `api/game.js`, 승부예측 `api/pick.js`)의 원칙을 그대로 따른다.

## 1. 원칙

| 원칙 | 이유 |
|---|---|
| **계산은 서버만** 한다 | 성장·기록·수상·커리어 점수를 브라우저에서 계산하면 랭킹을 조작할 수 있다 |
| **진행 상태는 암호화 토큰**(AES-256-GCM)으로 브라우저와 주고받는다 | Who Am I와 같은 방식. 시즌마다 KV를 쓰지 않는다(사용자 지정 — 무료 플랜 부담) |
| **KV는 랭킹에만** | 등록(커리어당 1번)과 랭킹 보기(30초 CDN 캐시)뿐 |
| **결과는 시드로 고정** | 커리어 시작 때 시드를 정하고 시즌 난수는 `시드 ^ hash(나이·선택)`. 되돌려 같은 선택을 하면 같은 결과 |
| **시뮬레이션 코드는 한 곳** | 서버 모듈 하나를 API와 밸런스 검증 스크립트가 같이 쓴다(목업처럼 브라우저에서 따로 돌리지 않는다) |

## 2. 파일 구성

| 파일 | 내용 |
|---|---|
| `api/_career_sim.js` | 순수 시뮬레이션 — 목업의 성장·출전·부상·기록·평점·우승·수상·발롱도르·이적 제안·방출·커리어 점수. 입력(상태+선택) → 출력(새 상태+시즌 결과). `fetch`·KV 없음 |
| `api/_career_data.js` | 15개국 298개 구단(이름·명성·Fotmob id), 카드·스탯·가중치, 국가 표(발탁 기준·강도·대륙컵), 이벤트 정의, 랜덤 이름 |
| `api/_token.js` | AES-GCM `seal`/`open`을 `game.js`에서 떼어 내 공용으로(키 파생 방식은 그대로 — 기존 Who Am I 토큰이 깨지면 안 된다) |
| `api/career.js` | 엔드포인트(아래 §3). `_account.js`로 로그인 확인 |
| `public/index.html` | 화면(§5). 게임 목록에 세 번째 카드 |
| `scripts/sim_career.mjs` | 밸런스 검증 — `_career_sim.js`를 그대로 불러 수천 커리어를 돌리고 `career-mode.md` §13 표와 같은 형식으로 출력. 밸런스를 고친 뒤 반드시 돌린다 |
| `scripts/build_career_clubs.mjs` | 시즌이 바뀔 때 Fotmob 리그 순위표에서 구단 목록을 다시 받아 `_career_data.js`의 구단 부분을 갱신(명성은 기존 값 유지, 새 구단만 표시해서 손으로 정함). 크론 없음 |

## 3. API (`/api/career?a=…`, 모두 POST + JSON, `board`·`card`만 GET)

| a | 입력 | 출력 | KV |
|---|---|---|---|
| `new` | 이름·국적·주발·포지션·등번호·꿈의 구단·카드 | 토큰 + 첫 구단 3곳 | — |
| `join` | 토큰 + 고른 구단 | 토큰 + 시즌 준비(목표·이벤트) | — |
| `season` | 토큰 + 훈련 방향 + 이벤트 선택 (+ 부상 처리 선택) | 부상이면 `{injury}` 질문과 토큰, 아니면 시즌 결과 + 이적 제안 + 토큰 | — |
| `next` | 토큰 + 고른 제안(없으면 잔류) | 토큰 + 다음 시즌 준비 | — |
| `retire` | 토큰 | 은퇴 카드 데이터 + 커리어 점수 + 토큰(은퇴 상태) | — |
| `submit` | 은퇴 토큰 + 로그인 | 순위 | 등록 1회 |
| `board` | — | TOP 100 | 읽기(캐시) |
| `card` | 계정 키 | 그 계정의 대표 은퇴 카드 | 읽기 |

- 부상은 시즌 중간 질문이라 `season`을 두 번 부른다(첫 호출이 부상을 알려 주면 선택을 담아 다시). 부상 굴림은 시즌 결과와 다른 난수열을 써서 두 번 불러도 결과가 바뀌지 않는다(목업과 같음).
- 서버는 토큰의 `phase`를 확인해 순서를 강제한다(`season` 전에 `next` 불가 등).
- 각 응답은 화면을 그리는 데 필요한 것만 준다. **숨은 재능·구단 명성 숫자·발롱 점수 같은 숨김 값은 응답에 넣지 않는다**(토큰은 암호화라 안 보인다).

## 4. 토큰

- 담는 것: 버전, 시드, 커리어 id, 단계(`phase`), 나이, 오버롤·오프셋 5개, 약발, 숨은 재능·유스 성실도, 명성·수상 보너스, 소속·임대·방출 상태, 부상 상태(유리몸·보존 치료 남은 시즌 등), 통산 합계, 시즌 기록(나이별 한 줄), 수상 목록.
- 크기: 지난 시즌 줄은 은퇴 카드에 필요한 값만 남기고(메모·스탯 변화는 버림) 수상 목록은 시즌 줄에서 다시 만든다. 평문 최대 약 8KB를 deflate한 뒤 암호화해서 **토큰은 최대 약 2.4KB**(실측). 브라우저 `localStorage`에 저장해 **같은 기기에서 이어 하기**가 된다.
- 토큰 키 파생 라벨은 게임마다 다르다(`career-token-v1` / Who Am I `whoami-token-v1`) — 한 게임의 토큰을 다른 게임에 보내도 열리지 않는다.
- **버전 필드(`v`)**: 형식 호환용(§8-3). 필드 구조가 바뀌면 옛 토큰을 읽을 때 기본값을 채운다.
- 약점(알려진 것, Who Am I와 같음): 옛 토큰을 다시 보내 **다른 선택**을 해 볼 수는 있다(같은 선택은 같은 결과). 막으려면 시즌마다 KV에 진행 단계를 적어야 해서 하지 않는다. 대신 이벤트·이적 선택 결과의 대부분이 "운"이 아니라 "트레이드오프"라 되돌려 얻는 이득이 작다.

## 5. 화면(`index.html`)

목업 화면을 그대로 옮긴다. 순서: 선수 만들기 → 선수 유형 → 첫 구단 → (시즌 준비 → [부상] → 시즌 결과·이적시장) 반복 → 은퇴 카드 → 랭킹.

- 게임 목록: 승부예측 / Who Am I 아래(또는 사이)에 **커리어 모드** 카드. 진행 중인 커리어가 있으면 "이어 하기 · 정민준 24세".
- 화면은 서버 응답만 그린다(계산 코드 없음). 트로피 SVG·엠블럼·국기·오버롤 색 단계(80/90/95)는 프론트.
- 구단 목록(꿈의 구단 고르기)은 `board`처럼 캐시되는 GET으로 받거나, 이름만 작은 JSON으로 내려받는다(298개 × 이름 ≈ 6KB).
- 내 정보 모달에 "커리어 모드 최고 기록"(점수·순위·선수 이름) 한 줄 추가.
- PC 레이아웃: 시즌 화면은 2:1(좌 시즌·이적 / 우 선수 카드·커리어 기록), 은퇴 카드·랭킹은 가운데 600px.

## 6. 랭킹 저장(KV)

| 키 | 내용 |
|---|---|
| `career:board:v1` | 정렬 집합. 멤버 `@{계정키}`, 점수 = 커리어 점수. 상위 1,000개만 유지 |
| `career:card:{계정키}` | 대표 커리어의 은퇴 카드 요약 JSON(1~2KB). 1,000위 밖으로 밀리면 지운다 |
| `career:done:{커리어id}` | 같은 커리어 두 번 등록 방지(NX, 30일) |
| `career:reg:{YYYY-MM}` | 월 등록 수(상한 — Who Am I와 같은 무료 한도 보호) |

- 계정당 최고 기록 하나: 새 점수가 기존보다 높을 때만 교체(카드도 같이).
- 닉네임 표시는 `pk:names`(닉네임 변경 반영).

## 7. 작업 순서

| 단계 | 내용 | 확인 |
|---|---|---|
| 1 | `_career_data.js`·`_career_sim.js`로 목업 로직 이식, `_token.js` 분리 | `scripts/sim_career.mjs` 결과가 문서 §13 표와 같은지(재능별 정점, 수상 빈도, 발롱도르, 포지션별 점수, 부상·은퇴 나이) |
| 2 | `api/career.js`(new/join/season/next/retire) | 가짜 req/res로 한 커리어를 끝까지, 같은 선택 재요청 시 같은 결과, 단계 순서 위반 거부, 토큰 크기 |
| 3 | 화면 이식 + 게임 목록 카드 + 이어 하기 | 로컬 서버(KV 목업) + Playwright로 모바일·PC 스크린샷, 부상·방출·은퇴 경로 |
| 4 | submit/board/card + 내 정보 연동 | KV 목업으로 등록·교체·1,000위 컷·카드 열람 |
| 5 | CLAUDE.md "미니게임" 절에 커리어 모드 규칙 추가, 미리보기 확인 → "반영" | 미리보기 주소에서 실제 엠블럼·이미지 확인 |

규모 감: 서버 약 900줄(시뮬 600 + API 200 + 데이터), 화면 JS·CSS 약 1,200줄. 1~2단계와 3~4단계를 나눠 두 번에 나눠 반영하는 걸 권한다(서버만 먼저 올려도 화면이 없으니 사용자에겐 안 보인다).

## 8. 결정 사항(사용자 지정)

1. 게임 목록 카드 순서: **승부예측 / 커리어 모드 / Who Am I?**
2. 이어 하기는 **같은 기기에서만**(토큰을 `localStorage`에). 다른 기기 이어 하기용 KV 저장은 하지 않는다.
3. 밸런스 버전 차단은 넣지 않는다 — 큰 밸런스 변경 계획이 없다. 토큰의 `v`는 형식 호환용으로만 둔다(필드 구조가 바뀌면 옛 토큰을 읽을 때 기본값을 채운다).
